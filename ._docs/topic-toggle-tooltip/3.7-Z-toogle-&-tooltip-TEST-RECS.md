  UI / Functionality Improvement Recommendations

  Based on comprehensive analysis of all screenshots, code review, and the E2E testing walkthrough:

  1. INCONSISTENT DEFAULT STATES - High Priority

  Problem: The "Use as ref" checkbox defaults to CHECKED in EnhancedUploadModal but UNCHECKED in Stage 8 and Stage 10. This      
  creates a confusing mental model. A user who learns "the toggle is on by default" in Stage 5 will be surprised when it's off   
  elsewhere.

  Recommendation: Make the default consistent across all locations. Since the purpose is to use the current image as a
  style/composition reference during regeneration, defaulting to ON everywhere makes sense -- the user already has an image they 
  presumably like. If the user wants a completely fresh generation, they can uncheck.

  ---
  2. INCONSISTENT LABEL TEXT - Medium Priority

  Problem: The checkbox label is "Use as ref" in EnhancedUploadModal and Stage 8, but "Use current image as reference" in Stage  
  10 FramePanel. Three different lengths for the same concept.

  Recommendation: Standardize on a single label. "Use as ref" is compact but cryptic for new users. "Use current image as        
  reference" is clear but long. Consider: "Use current as reference" everywhere, or keep "Use as ref" but add a tooltip
  explaining what it means (like the button tooltips already do).

  ---
  3. CHECKBOX IS TOO SMALL AND EASY TO MISS - High Priority

  Problem: The "Use as ref" checkbox uses text-[10px] styling, making it extremely small (visible in screenshots - it's a tiny   
  circle with tiny text). On the EnhancedUploadModal, it's placed on the second row of action buttons next to "Regenerate",      
  visually subordinate. In Stage 8, it's between the "Generate Image" button and "Drop image or click to upload" -- easy to      
  overlook entirely.

  Recommendation:
  - Increase to at least text-xs (12px) for readability
  - Consider making it a more prominent toggle switch instead of a checkbox, or add a subtle highlight/border when checked to    
  give visual feedback
  - In the EnhancedUploadModal, consider placing it inline with a tooltip that says "When checked, the AI uses the current image 
  as a style and composition guide for regeneration"

  ---
  4. NO EXPLANATION OF WHAT "USE AS REF" ACTUALLY DOES - High Priority

  Problem: The Regenerate button has an excellent tooltip ("Generate a new image from the Final Description. When 'Use as ref' is   on, the current image guides style and composition.") but the checkbox itself has NO tooltip. A user seeing "Use as ref" for  
  the first time has no idea what it means. In Stage 8 and Stage 10, there's no explanatory tooltip at all.

  Recommendation: Add an info icon tooltip next to the "Use as ref" label (consistent with the info tooltips on "Extracted from  
  Image" and "Final Description" labels). The tooltip should explain: "When checked, the current image is sent as a style        
  reference to guide the generation, helping maintain visual consistency."

  ---
  5. NO VISUAL FEEDBACK WHEN REGENERATING WITH/WITHOUT REF - Medium Priority

  Problem: After clicking Regenerate with "Use as ref" checked vs unchecked, there's no visual indication to the user of what    
  mode they chose. If the generation takes 15-30 seconds, the user may forget whether they used the reference or not.

  Recommendation: When regeneration starts, show a brief toast or inline status message like "Regenerating with reference        
  image..." or "Regenerating from description only..." to confirm the user's choice.

  ---
  6. BUTTON TOOLTIPS HAVE NO DELAY DIFFERENTIATION - Low Priority

  Problem: All tooltips use the same delayDuration={300}. When hovering quickly across adjacent buttons (Edit Image -> Apply     
  Style -> Remove BG -> Regenerate), tooltips from previous buttons can interfere with the next (this caused 4 "failures" in E2E 
  testing). The tooltips compete.

  Recommendation: The TooltipProvider wrapping could benefit from a slightly longer skipDelayDuration (currently defaults to 0,  
  meaning instant re-trigger). Consider skipDelayDuration={100} to give a brief "cooldown" between sequential tooltip triggers.  

  ---
  7. STAGE 8 "GENERATE IMAGE" vs "USE MASTER AS-IS" RELATIONSHIP IS UNCLEAR - Medium Priority

  Problem: In Stage 8, the "Generate Image" button and "Use as ref" checkbox sit below both the Master reference and Scene       
  instance images. It's not immediately clear: "Generate a new image using what as input? The master? The scene instance? The    
  description?" The checkbox adds another layer of ambiguity.

  Recommendation: Add a brief inline label above the button area: "Generate new scene image from description" with the checkbox  
  as a modifier. Or rephrase the button: "Generate from Description" when unchecked, "Generate from Description + Current Image" 
  when checked.

  ---
  8. TRANSFORMATION EVENT CHECKBOX VISIBILITY IS GATED BUT NOT EXPLAINED - Low Priority

  Problem: The transformation post-image "Use as ref" checkbox only appears when event.post_image_key_url exists AND
  onGeneratePostImage is provided. If a user sees the Generate Image button but no checkbox, they may not understand that the    
  checkbox will appear after the first image is generated.

  Recommendation: Show the checkbox in a disabled state with a tooltip "Available after first image is generated" when no        
  post-image exists yet. This teaches the user the feature exists before they can use it.

  ---
  9. STAGE 10 FRAME UPLOAD BUTTON IS NEARLY INVISIBLE - Medium Priority

  Problem: The frame upload button in Stage 10 is an icon-only button (small Upload icon) next to "Start Frame / Pending" with no   label. During E2E testing, it was extremely difficult to locate programmatically and would be similarly hard for users to     
  discover.

  Recommendation: Add a text label "Upload" below the icon, or make the empty frame area itself a drop zone with a visible       
  "Upload or drag image" message (similar to Stage 8's "Drop image or click to upload" pattern).

  ---
  10. POTENTIAL ADDITION: BATCH "USE AS REF" TOGGLE - Nice to Have

  Problem: In Stage 10, if a user wants to regenerate multiple frames with reference images, they need to open each shot's regen 
  panel and toggle the checkbox individually for every frame.

  Recommendation: Add a global toggle at the top of the Frame Generation page: "Use existing frames as reference for all
  regenerations" that sets the default for all subsequent regen operations in that session.
