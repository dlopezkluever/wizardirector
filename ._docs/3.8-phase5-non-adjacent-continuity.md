## Phase 5 — Non-Adjacent Frame Continuity References (Topic 5)

### Problem Statement
The current camera angle change reference system only supports adjacent frame references — a shot's start frame references the previous shot's end frame. But many shot sequences aren't linear. Shot-reverse-shot patterns alternate between two camera positions (shots 1, 3, 5 share one angle; shots 2, 4, 6 share another). Adjacent references can't capture this.

### Core Goal
Allow users to manually link non-adjacent frames as continuity references for each other. Shot 1B and Shot 1E should be linkable even though they're not sequential. Extend the existing frame_links infrastructure to support many-to-many linking.

### Relevant Files

**Backend:**
- `backend/src/services/frameGenerationService.ts` — `generateWithCameraChangeAnalysis()` (~line 325-360): looks up `frame_links` for reference frame, passes to vision analysis. `fetchShotReferenceImages()`, `resolveEndFrameReferenceImages()`
- `backend/src/routes/frames.ts` — frame CRUD + `add-frame-as-reference` route for creating links. GET endpoint returns `prevSceneEndFrame` and `nextSceneStartFrame` as adjacent references
- Database: `frame_links` table (migration 035) with `source_frame_id`, `target_frame_id`, `link_type` ('match'|'reference'), **UNIQUE constraint on `target_frame_id`** — this is the blocker for many-to-many

**Frontend:**
- `src/components/pipeline/Stage10FrameGeneration.tsx` — FramePanel with 4 directional buttons: "Match from", "Ref from", "Push Match to", "Push Ref to"
- Continuity link status badges (blue/amber for match, emerald/violet for reference)

**Image analysis:**
- `backend/src/services/imageAnalysisService.ts` — `analyzeReferenceFrame()`: Gemini 2.5 Flash vision analysis of reference frame, outputs "WHAT MUST BE PRESERVED" / "WHAT CHANGES" sections

### Current State

The `frame_links` table supports linking frames with two types:
- `match`: Copy previous shot's end frame directly (zero generation cost)
- `reference`: Analyze reference frame with vision AI, generate enhanced continuity prompt

**Critical constraint:** `UNIQUE(target_frame_id)` means each frame can only have ONE incoming reference link. This prevents many-to-many linking needed for shot-reverse-shot patterns.

The UI has 4 directional buttons for creating links, plus continuity mode selection per shot (`none`, `match`, `camera_change`). Adjacent frame data (`prevSceneEndFrame`, `nextSceneStartFrame`) is fetched for cross-scene continuity.

### Implementation Notes

**Step 1 — Schema change: Remove UNIQUE constraint on target_frame_id:**
- Migration: `ALTER TABLE frame_links DROP CONSTRAINT frame_links_target_frame_id_key;`
- Add a composite unique: `UNIQUE(source_frame_id, target_frame_id)` to prevent duplicate links between the same pair
- This allows a frame to have multiple incoming references

**Step 2 — Define reference selection behavior:**
When a frame has multiple reference links, how does `generateWithCameraChangeAnalysis()` pick which one to use?
- Option: Use the most recent link (by created_at) as the primary reference
- Option: Analyze ALL linked references and merge their visual analysis
- Recommended: Let the user designate a "primary" reference. Add `is_primary BOOLEAN DEFAULT false` to frame_links. Generation uses the primary. Others serve as secondary references that enrich the continuity prompt.

**Step 3 — Backend: Update frame link queries:**
- `frameGenerationService.ts`: Update the reference frame lookup to handle multiple links
- If using primary reference: query `WHERE target_frame_id = ? AND is_primary = true`
- Pass secondary references as additional context to `analyzeReferenceFrame()`

**Step 4 — Backend: Update generation flow:**
- When generating with camera_change: primary reference frame gets full vision analysis
- Secondary references: include their URLs as additional reference images (identity role) without full vision analysis
- This keeps generation cost reasonable while benefiting from multiple references

**Step 5 — Frontend: UI for non-adjacent linking:**
- Current UI only shows adjacent frames (prev/next). Need a way to browse and select any frame in the scene (or across scenes).
- Add a "Link Reference Frame" button that opens a frame picker:
  - Show thumbnails of all generated frames in the current scene
  - Optionally show frames from adjacent scenes
  - User clicks to create a reference link
- Show linked frames as small thumbnails below the current frame
- Allow removing links
- Mark primary reference with a star/badge

**Step 6 — Frontend: Visual indicators for linked frames:**
- Shots that share reference links should show visual indicators (e.g., colored dots or connecting lines in the shot list)
- Shot-reverse-shot pairs: color-code matching groups (shots 1, 3, 5 = blue; shots 2, 4, 6 = green)
- This gives users a visual map of continuity relationships

### Dependencies
- Phase 1 (4D.2) — reference images must work correctly before extending the system
- No dependency on Phases 2-4 — this is an independent feature

### Notables
- The UNIQUE constraint removal is a small migration but changes the semantics of frame_links fundamentally. All existing queries that assume one-to-one must be audited.
- Vision analysis cost: `analyzeReferenceFrame()` calls Gemini 2.5 Flash per reference. Multiple references per frame could increase costs. The primary/secondary split mitigates this — only primary gets full analysis.
- Shot-reverse-shot is the most common use case, but this also enables: recurring establishing shots, flashback references, dream sequence callbacks, etc.
- The frame picker UI could reuse patterns from the existing ContentAccessCarousel (mentioned in 3.7-Do-last doc as already built).
- Cross-scene references are already partially supported (prevSceneEndFrame/nextSceneStartFrame). Extending to arbitrary frames within and across scenes is the goal.
