# Phase 0: Investigation & Verification

## Core Goal
Verify and fix the asset generation and inheritance chains before building new features on top of them. Two investigations that must complete first: (A) scene instance regen quality, and (B) the full asset inheritance chain from Stage 5 through Stage 10.

---

## Investigation A: Scene Instance Regen Quality (Task 1.2)

### Problem Statement
Scene instance image regeneration may not correctly combine: master reference image + visual description override + status tags. The spec flags several failure modes:
- Style transfer not working (photo uploaded as character asset -> regen to Pixar style produces unrecognizable result)
- Status tags not influencing generation (e.g., "muddy", "bloody" tags ignored)
- Visual description overrides not overriding master description in generation prompt
- Transformation post-descriptions not producing correct visuals

### What to Verify

#### 1. Scene Instance Image Generation Prompt Assembly
- **File**: `backend/src/routes/projectAssets.ts` (scene asset generate-image endpoint)
- **Check**: What prompt is actually sent to the image generation API?
  - Is `effective_description` (override > master) used, or just master description?
  - Are `status_tags` included in the generation prompt?
  - Is the master reference image / selected master reference attached as a reference image?
  - Is the visual style capsule applied?

#### 2. Master Reference as Generation Input
- **File**: `backend/src/services/imageGenerationService.ts`
- **Check**: When generating a scene instance image, is `selected_master_reference_url` passed as a reference image to the API?
- **Expected behavior**: The generation should use the master ref as visual identity anchor + the effective_description as the prompt + status tags as modifiers + visual style capsule for aesthetic

#### 3. Style Transfer Use Case
- **Test**: Upload a real photo as character asset in Stage 5 (Pixar-style project). Navigate to Stage 8. Generate scene instance image.
- **Expected**: Output should look like the person but in Pixar style
- **Check**: Is the uploaded image passed as `referenceImageUrl` to the gen API? Is the visual style capsule prompt prepended/appended?

#### 4. Status Tags in Generation
- **Files**: `src/components/pipeline/Stage8/VisualStateEditorPanel.tsx`, backend generation endpoint
- **Check**: When user has status tags like "muddy", "torn clothing" — do these appear in the generation prompt?
- **If missing**: Add status tags to the prompt assembly (append to effective_description or as a separate directive)

#### 5. Transformation Post-Description Generation
- **Check**: When generating a post-transformation image, is `post_description` used as the prompt?
- **Check**: Is the pre-transformation image passed as reference (for visual identity continuity)?

### Relevant Files
| File | Role |
|------|------|
| `backend/src/routes/projectAssets.ts` | Scene asset image generation endpoint |
| `backend/src/services/imageGenerationService.ts` | Image job creation and execution |
| `src/lib/services/sceneAssetService.ts` | Frontend scene asset API client |
| `src/components/pipeline/Stage8/VisualStateEditorPanel.tsx` | Generation trigger UI |
| `backend/src/services/promptGenerationService.ts` | May contain scene instance prompt logic |

### Expected Fixes
- If status tags are not in the prompt: add them
- If master reference image is not attached: attach it
- If effective_description is not used: fix to use override chain
- If visual style capsule is not applied to scene instance gen: apply it

## Investigation B: Asset Inheritance Chain (Task 4D.2)

### Problem Statement
Generated frames in Stage 10 reportedly show no influence from master assets. Characters look completely different from their Stage 8 scene instance images. The full inheritance chain (Stage 5 -> 8 -> 9 -> 10) may be broken.

### What to Verify

#### 1. Stage 9: Reference Image Order Assembly
- **File**: `backend/src/services/promptGenerationService.ts`
- **Function**: `buildNumberedImageManifest()`
- **Check**: What URLs end up in `referenceImageOrder`?
  - Priority should be: `matched_angle_url > image_key_url > master_image_url`
  - `image_key_url` = scene instance image (Stage 8 generated)
  - `master_image_url` = Stage 5 master asset image
  - **Bug suspect**: Is `master_image_url` being used when `image_key_url` exists? (Spec flags this as a known issue: "master reference image being passed instead of scene instance image")

#### 2. Stage 9: Reference Images Stored on Shots
- **Table**: `shots.reference_image_order` JSON column
- **Check**: After prompt generation, do the stored URLs point to scene instance images or master images?
- **Debug**: Log the actual URLs stored and trace them back to their source

#### 3. Stage 10: Reference Images Fetched for Generation
- **File**: `backend/src/services/frameGenerationService.ts`
- **Function**: `fetchShotReferenceImages()`
- **Check**: Are the URLs from `reference_image_order` actually fetched and passed to the image gen API?
- **Check**: Are the URLs still valid (not expired signed URLs, not deleted images)?

#### 4. Stage 10: Image Generation API Call
- **File**: `backend/src/services/imageGenerationService.ts`
- **Function**: `executeJobInBackground()` / `createImageJob()`
- **Check**: Are reference images actually included in the API call to Gemini/Flux/Veo?
- **Check**: Are identity reference images placed BEFORE style reference images? (Identity should take priority)

#### 5. End Frame Reference Images
- **File**: `backend/src/services/frameGenerationService.ts`
- **Function**: `resolveEndFrameReferenceImages()`
- **Check**: Are end frame refs correctly swapping in post-transformation images?
- **Check**: Is the start frame prepended as identity reference for the end frame?
- **Bug suspect**: End frames may just be copying start frame refs without transformation swaps

#### 6. Shot-to-Asset Assignment Presence Types
- **Check**: Are `shot_asset_assignments` correctly populated with presence types?
- **Check**: Do "enters" assets correctly appear only in end frame refs? Do "exits" assets appear only in start frame refs?

### Relevant Files
| File | Role |
|------|------|
| `backend/src/services/promptGenerationService.ts` | Builds reference image manifests (Stage 9) |
| `backend/src/services/frameGenerationService.ts` | Fetches and passes refs to image gen (Stage 10) |
| `backend/src/services/imageGenerationService.ts` | Actual API calls with reference images |
| `backend/src/services/transformationEventService.ts` | Resolves per-shot overrides |
| `backend/src/routes/frames.ts` | Frame generation endpoints |
| `backend/src/routes/projects.ts` | Prompt generation endpoint (Stage 9) |

### Debugging Approach
1. Add temporary logging to `buildNumberedImageManifest()` showing each asset's resolved URL and source
2. Add logging to `fetchShotReferenceImages()` showing what's being read from the DB
3. Add logging to `createImageJob()` showing the final reference image array sent to the provider
4. Generate a test scene and trace the full flow end-to-end
5. Compare: does the Stage 10 output visually resemble the Stage 8 scene instance images?

### Expected Fixes
- Fix URL priority if scene instance images are being skipped for master images
- Fix any broken URL references (expired, missing)
- Ensure reference images are in correct order (identity first, style second)
- Fix end frame reference resolution if transformation swaps are missing
