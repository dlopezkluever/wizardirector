# Phase 6: Shot-to-Shot Prompt Chaining (WT-E)

## Core Goal
Pipe prior shot context into subsequent prompts within a scene for action continuity. Each shot's prompt should be aware of what happened in the previous shot, creating a chain of visual/narrative state.

---

## Problem Statement
Each shot's prompt is currently generated independently. Shot 1 ends with a character sitting down, but Shot 2's prompt has no awareness of this — the character might be described as standing. This breaks visual continuity within a scene.

---

## Current State

### Existing Infrastructure
- **`generateBulkPromptSets()`** in `promptGenerationService.ts`: Processes shots sequentially within a scene. Already has a 4th param `transformationEvents?: TransformationEvent[]` and resolves per-shot overrides via `resolveOverridesForShot()`.
- **`generatePromptSet()`**: Generates frame + video + end frame prompts for a single shot. Has 4th param `shotOverrides?: ShotAssetOverride[]`.
- **Transformation system**: Already handles description swaps per-shot. Chaining should carry *action/position state*, not re-derive appearance (transformation overrides handle that).
- **`PromptSet` type**: Already has `transformationContext?: PromptSetTransformationContext[]`.
- **Stage 9 UI**: Already has transformation state badges (Pre-Transform / Transforming / Post-Transform) and ContentAccessCarousel.

### What Does NOT Exist
- No "shot end state" extraction
- No chaining context injection between shots
- No cumulative scene state tracking
- No UI for viewing/editing chained context
- No toggle for chaining on/off

---

## Implementation Notes

### Core Chain Logic

Inside `generateBulkPromptSets()`:

```
For each shot in sequential order:
  1. Resolve transformation overrides (existing code)
  2. If shot > 1 AND chaining enabled:
     a. Take previous shot's prompts + shot data + resolved overrides
     b. Extract "shot end state" summary via LLM
     c. Inject summary into this shot's generation context
  3. Generate this shot's prompts (with chain context if available)
  4. Store chain context alongside prompts
```

### Shot End State Extraction

New function: `extractShotEndState(shot, promptSet, resolvedOverrides)`

LLM prompt:
```
Given this shot's frame prompt, video prompt, and end frame prompt, extract a concise
"end state summary" capturing:

1. Character positions (where each character is in the frame at shot's end)
2. Character states (posture, expression, action completed)
3. Prop states (anything moved, broken, changed)
4. Environmental changes (lighting shift, door opened, etc.)
5. Emotional beat (the mood/tension at shot's end)

If a transformation occurred in this shot, note the post-transformation state:
{transformation context from resolved overrides}

Output: A compact paragraph (3-5 sentences) describing the visual end state.
Do NOT include camera information — only subject/environment state.
```

**Critical**: If `resolveOverridesForShot()` returned overrides for this shot (transformation occurred), the end state MUST reflect the `post_description`, not the original `effective_description`.

### Chain Context Injection

When generating Shot N (N > 1):
- Add to the user prompt for `generateFramePrompt()`:
  ```
  PRIOR SHOT CONTEXT:
  At the end of the previous shot, the visual state was:
  {previousShotEndState}

  Maintain continuity: character positions, expressions, and physical states
  should naturally continue from this prior state unless the action explicitly
  changes them.
  ```

- The chain context supplements (not replaces) transformation overrides. Overrides handle *which description* to use; chaining handles *action/position/state continuity*.

### Cumulative vs Rolling Context

Two approaches:
1. **Rolling** (recommended): Each shot only sees the immediately previous shot's end state. Simple, bounded context size.
2. **Cumulative**: Each shot sees ALL prior end states. Richer but context grows with scene length, risking prompt bloat.

Recommendation: Rolling (shot N sees only shot N-1's end state). If a shot needs awareness of shot N-3, the chain naturally carries forward through N-2 and N-1.

### Data Model

Add to `PromptSet` type in `src/types/scene.ts`:
```typescript
chainedContext?: string;  // The end state summary for this shot (output)
priorChainContext?: string;  // The injected context from previous shot (input)
```

Store on the `shots` table:
```sql
ALTER TABLE shots ADD COLUMN chained_context TEXT;
ALTER TABLE shots ADD COLUMN prior_chain_context TEXT;
```

Scene-level toggle:
```sql
ALTER TABLE scene_states ADD COLUMN chain_prompts BOOLEAN DEFAULT TRUE;
```

### Stage 9 UI Changes

`Stage9PromptSegmentation.tsx`:

1. **Scene-level toggle**: "Chain prompts" ON/OFF switch at the top of the scene view. Default: ON for scenes with 2+ shots.

2. **Per-shot chain context display**: Above each shot's prompts (except Shot 1), a collapsible section:
   ```
   [v] Context from prior shot
   "At the end of Shot 1, Alice is seated at the kitchen table,
    elbows on surface, head in hands. Bob stands behind her,
    hand on her shoulder. The room is dimly lit, single overhead
    lamp casting warm pool of light."
   ```
   - Editable: user can modify the chained context
   - "Regenerate from here" button: re-chains from this shot forward (re-extracts end states for all subsequent shots)

3. **Visual indicator**: Small chain icon between shot cards when chaining is active. Broken chain icon when OFF.

4. **Coexistence with transformation badges**: Chain context section sits BELOW the transformation state badges. Both are visible simultaneously.

### "Regenerate from Here" Flow

When user edits a shot's chain context or clicks "Regenerate from here":
1. Use the edited chain context as the input for this shot
2. Regenerate this shot's prompts with the new chain context
3. Extract new end state from regenerated prompts
4. Chain forward: regenerate Shot N+1 with new end state, then N+2, etc.
5. This is sequential and may take time for long scenes — show progress indicator

## Notables
- Chaining is inherently sequential — it cannot be parallelized. This means `generateBulkPromptSets()` remains sequential (it already is). The extra LLM call for `extractShotEndState()` adds latency per shot.
- For a 10-shot scene: 10 prompt generations + 9 end-state extractions = ~19 LLM calls (vs 10 without chaining). Expect roughly 2x generation time. Users should be warned.
- The chain context is a new save state — it's editable and persisted. This gives users fine-grained control over continuity without modifying the prompts themselves.
- Edge case: Shot 1 has no prior context. Its end state is extracted purely from its own prompts. If Shot 1's prompts are vague, the chain starts weak. Consider adding a "scene opening state" that the user can set (e.g., "Scene opens with all characters seated around the table").
