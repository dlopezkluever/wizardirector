### 1. Asset Description Updates on Image Upload (Stages 5 & 8)

The core problem: agentic extraction from Stage 4 won't always match the user's vision, and users may upload their own custom asset images that differ meaningfully from the auto-generated description.

#### When a user uploads an image, trigger a **Description Reconciliation Modal** with 3 columns:
- **Column A** — Existing description (what was already in place)
- **Column B** — Extracted description (auto-analyzed from the uploaded image)
- **Column C** — Editable merge field (user builds the final description by pulling from A, B, and adding their own input)

#### Agentic tools available within the modal:
- **Merge Descriptions** — User specifies which parts of A and B to keep; AI merges them into one cohesive, thorough description
- **Tag-Based Adjustment** — User keeps either the original or extracted description as the base, then adds directional tags (e.g. `jumpsuit`, `wet`, `bloody`, `sad`, `sweaty`) that the AI applies to produce the final result

#### Two upload intent modes to account for:
1. **Full replacement** — the uploaded image *is* the asset; description should update to reflect it accurately
2. **Starting point** — the uploaded image is a reference to iterate from; user wants to edit toward their final vision (e.g. character is in a suit in the upload, but needs to be in a prison jumpsuit in the story)

### 2. Story-Aware Description Updating (Stage 8)

As the story evolves, asset descriptions inherited from earlier stages can become stale or inaccurate.

- Add a **"Update from Story Context"** button on asset description fields in Stage 8
- When triggered, an agentic tool reads the **script, treatment, and beat sheet** to understand what's happening in the story at that point, then proposes an updated description that reflects the narrative context
- This updated version becomes a new **save state** in the existing version history system (not a replacement — all prior versions remain accessible)
- Fits naturally into the carousel/save-state pattern already discussed: original → edited → story-updated → further tweaked → all cycleable
