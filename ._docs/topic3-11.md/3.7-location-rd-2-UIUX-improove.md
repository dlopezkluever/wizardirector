 UI/UX Improvement Recommendations — Location System Overhaul

  Critical Issues

  1. "Camera Directions" is completely inaccessible for deferred locations
  The "Camera Directions" menu item only appears on the kebab dropdown for active assets in Stage 5. Since   
  the asset extraction deferred all 8 location assets, there is literally no way for the user to set up      
  camera directions until they manually activate a location. This is a major workflow gap — the user may not 
  even know the feature exists.

  Recommendation: Either (a) add a "Camera Directions" menu item to deferred asset rows too, or (b) add a    
  prominent "Set Up Camera Directions" entry point from Stage 8's LocationCoveragePanel directly (since      
  that's where the user first encounters the problem of unassigned shots), or (c) auto-promote locations to  
  active when they appear in scene dependencies.

  2. LocationCoveragePanel shows "0/3 shots covered" but gives no guidance on what to do
  The amber warning banner ("3 unassigned shot(s)") is visible, but the dropdowns all say "Unassigned" with  
  no direction options. The user sees a problem but has no way to fix it because no directions have been     
  defined yet. There's no link or call-to-action to "Go define camera directions first."

  Recommendation: Add an empty-state message when there are 0 directions defined: "No camera directions      
  defined for this location. [Set up directions in Stage 5] to enable shot assignment." Include a direct     
  link/button that opens the LocationViewsDialog or navigates to Stage 5.

  3. Coverage Panel direction dropdown shows only "Unassigned" when no views exist
  The dropdown for assigning shots to directions opens but only shows "Unassigned" as the sole option. This  
  is confusing — the user clicks expecting to assign a shot but has nothing to assign to.

  Recommendation: When there are 0 directions, either (a) hide the dropdown entirely and show a "Set up
  directions first" message, or (b) show a disabled state with tooltip explaining why, or (c) add an inline  
  "Create direction" quick-action in the dropdown.

  Moderate Issues

  4. No visual connection between Stage 5 Camera Directions and Stage 8 Coverage Panel
  These are two separate features that are tightly coupled (you define directions in Stage 5, then assign    
  shots in Stage 8), but there's no navigation or visual link between them. The user has to manually figure  
  out the workflow.

  Recommendation: Add bidirectional navigation: from Coverage Panel → "Define directions" link to Stage 5    
  LocationViewsDialog; from LocationViewsDialog → "See shot assignments" link to Stage 8 Coverage Panel.     

  5. Scene 02 (and other continuation scenes) has no location asset despite being in QLANKTON'S LAB
  Scene 02 shows "INT. QLANKTON'S LAB - CONTINUOUS" but its Stage 8 has only 1 character asset and no        
  location. The LocationCoveragePanel doesn't appear. This means continuation scenes don't inherit location  
  coverage analysis, even though they share the same physical space.

  Recommendation: Either (a) auto-inherit the location asset from the previous scene in continuous sequences,   or (b) show the coverage panel for scenes that have a recognized Expected Location even if no location    
  asset is explicitly linked, or (c) add a "Inherit assets from Scene 1" button that's more prominent.       

  6. "Deferred Assets (8)" section at bottom of Stage 5 buries important location assets
  All 8 location-related assets are in the deferred section, collapsed by default. Users who don't expand    
  this section will never discover that Camera Directions exists. The current project has only 2 active      
  characters and 0 active locations, which means the location system features are essentially invisible.     

  Recommendation: (a) When the user is on Stage 8 and sees unassigned shots, show a proactive notification:  
  "This scene's location 'QLANKTON'S LAB' is deferred. [Activate it] to enable camera direction assignment." 
  (b) Consider auto-activating location assets that appear in scene dependencies, since they're clearly      
  needed for production.

  7. Camera metadata display is text-only and could be more scannable
  Shot cards show "MS - Eye Level - Slow Dolly In" as plain text. While accurate, this is hard to parse at a 
  glance across many shots. There's no visual differentiation between distance, height, and movement.        

  Recommendation: Use color-coded badges or structured tags: [MS] [Eye Level] [Slow Dolly In] with distinct  
  visual treatment for each category. Or use icons — a small camera icon for distance, an arrow for height, a   motion indicator for movement.

  Minor / Polish

  8. Coverage Panel "0/3 shots covered" uses warning icon but no progress indicator
  The coverage status is just text. A visual progress bar (even a thin one) would make the coverage gap      
  immediately obvious at a glance.

  Recommendation: Add a thin progress bar (emerald fill) next to the "X/Y shots covered" text. Red/amber when   0%, partial amber, full emerald at 100%.

  9. The right sidebar stage navigation doesn't indicate which stages have location-related features
  Stages 8, 10 have new location coverage/establish features, but there's no visual indicator that these     
  stages have pending actions related to the location system.

  Recommendation: Add a small badge or dot on the Stage 8 sidebar icon when there are unassigned shots       
  (location coverage gaps), similar to how "Shot List" shows status dots.

  10. EstablishViewPrompt (Phase G) can't be tested but design concern noted
  The "Lock as Established View" feature requires a generated/approved frame + direction assignment. Given   
  that most shots in this project are unassigned to any direction, the feature may rarely trigger even when  
  Stage 10 is reached.

  Recommendation: Consider showing the establish prompt even for unassigned shots, with a dropdown to select 
  which direction to establish the frame for. This turns a passive feature into an active workflow step.     

  11. No "Quick Setup" wizard for the location direction system
  The entire location direction system requires the user to: (1) activate location assets, (2) open Camera   
  Directions dialog, (3) define directions, (4) go to Stage 8 Coverage Panel, (5) assign shots. This is 5    
  manual steps across 2 different stages with no guided flow.

  Recommendation: Add a "Set Up Location Directions" guided workflow that can be triggered from either Stage 
  5 or Stage 8. It would walk through: pick location → suggest default views → assign shots, all in a single 
  dialog/wizard flow. The "Suggest Default Views" feature already exists — it just needs to be more
  discoverable and connected to the assignment step.

  Potential Additions

  12. Auto-suggest direction assignments based on camera metadata
  Shots already have camera metadata (distance, height, movement). Directions have camera_distance and       
  camera_height. The matchShotToLocationView() scoring function exists in the backend but isn't exposed as a 
  UI feature.

  Recommendation: Add an "Auto-Assign Shots" button in the Coverage Panel that uses the deterministic        
  matching algorithm to pre-fill direction assignments based on camera metadata similarity. Show the user the   proposed assignments for review before committing.

  13. Coverage summary at the Script Hub level
  Currently, coverage is only visible per-scene in Stage 8. There's no project-wide view of which scenes have   location coverage gaps.

  Recommendation: Add a coverage indicator (red/amber/green dot) on each scene row in the Stage 7 Script Hub 
  sidebar, showing whether that scene has unresolved location coverage gaps. This helps the user prioritize  
  which scenes need attention.
