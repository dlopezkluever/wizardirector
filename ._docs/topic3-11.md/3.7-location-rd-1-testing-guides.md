## **Tests**:

Manual Testing Guide — Location System (Phases A–H)       

  Prereqs: A project with at least one scene that has a     
  location asset with a reference image. If you don't have  
  one, create a quick project and get through Stage 5 with a   location uploaded.

  ---
  Test 1: Camera Directions CRUD (Phases A, C) — Stage 5    

  1. Go to Stage 5 (Assets) → find a location asset
  2. Click the dropdown menu (⋯) → "Camera Directions"      
  3. Verify the dialog opens with 3 default views:
  Establishing + Direction 1 + Direction 2
  4. Edit Direction 1: set an alias (e.g. "Kitchen
  Counter"), add a description → Save
  5. Upload an image to Direction 1 via the upload button   
  6. Mark as primary if not already → confirm the primary   
  badge moves
  7. Close dialog, reopen → verify your edits persisted     

  Pass criteria: Views save, images upload, primary toggle  
  works.

  ---
  Test 2: Sub-location Precision (Phase B) — Stages 3–4     

  1. Generate/regenerate a script (Stage 3→4) for a scene   
  that logically has multiple rooms
  2. Check the scene headings — they should include
  sub-location specifics (e.g. INT. HOUSE - KITCHEN - DAY)  
  3. Go to Stage 4 → verify dependency extraction created   
  separate location assets for each sub-location

  Pass criteria: Script headings are spatially specific,    
  each sub-location extracts as its own asset.

  ---
  Test 3: Direction Assignment (Phase D) — Stage 7

  1. Go to Stage 7 → run shot extraction for a scene with a 
  location that has camera directions set up
  2. After extraction, check the shots — each should have   
  camera_direction_id assigned
  3. If the location had NO pre-existing directions, verify 
  new stage7_inferred directions were created (check back in   Stage 5 Camera Directions dialog — you should see new    
  entries with source stage7_inferred)
  4. Check that shots have structured camera metadata:      
  camera_distance, camera_height, camera_movement

  Pass criteria: Shots get direction assignments, new       
  directions created when missing, metadata populated.      

  ---
  Test 4: Coverage Panel (Phase E) — Stage 8

  1. Go to Stage 8 → look for the Location Coverage Panel   
  (should appear in the layout)
  2. Expand a location → verify it shows:
    - Each direction with shot count and source badge       
    - Directions with images show a green indicator, without   show a gap
    - "Unmatched shots" section (if any) with direction     
  assignment dropdowns
  3. If a shot is unmatched, assign it a direction via the  
  dropdown → confirm it updates

  Pass criteria: Coverage panel renders, gap detection      
  works, reassignment dropdown functions.

  ---
  Test 5: Prompt Generation with Direction Refs (Phase F) — 
  Stage 9→10

  1. In Stage 9, review the prompt for a shot that has a    
  direction with an image
  2. Look for 2 location references in the asset context:   
  matched direction (MAIN REFERENCE) + establishing view    
  (SPATIAL CONTEXT)
  3. Generate a frame in Stage 10 → verify the generated    
  frame visually reflects the location references

  Pass criteria: Prompt includes direction-specific
  references, generated frames show location consistency.   

  ---
  Test 6: Established Views (Phase G) — Stage 10

  1. In Stage 10, generate a frame for a shot whose
  direction has no image (a coverage gap)
  2. After frame generates → look for the emerald "This     
  fills a coverage gap!" banner below the frame
  3. Click "Lock as Established View" → confirm toast "View 
  established"
  4. Go back to Stage 8 coverage panel → verify the
  direction now shows an image (gap filled)
  5. Now do the same for a shot whose direction already has 
  an image:
    - Look for the subtle "Lock as established view for..." 
  text link
    - Click it → verify the replace dialog opens with       
  side-by-side comparison
    - Click "Replace" → confirm it updates

  Pass criteria: Gap-fill banner appears, locking works,    
  replace dialog shows comparison.


## **More Tests (longer, less Focused)**:

  ---
  Manual Testing Guide

  Prerequisites

  - A project with at least one script generated (through Stage 4)
  - Backend running (npm run dev in backend/)
  - Frontend running (npm run dev in project root)
  - Migration 038 applied to your Supabase instance

  ---
  Test 1: Sub-location Precision (Phase B)

  Where: Stage 3 → Stage 4 script generation

  1. Create a new project or use an existing one
  2. Generate a script (Stage 3 → 4) with a story that involves characters moving   
  between rooms (e.g., "a chase through an apartment")
  3. Verify: Scene headings should use compound format: INT. APARTMENT - KITCHEN -  
  DAY, not just INT. APARTMENT - DAY
  4. Verify: Action lines should describe WHERE characters are spatially ("She      
  crosses to the window", not just "She looks worried")
  5. Proceed to Stage 4 dependency extraction
  6. Verify: Each sub-location appears as a separate location dependency (e.g.,     
  "APARTMENT - KITCHEN" and "APARTMENT - HALLWAY" are two distinct entries, not     
  collapsed into "APARTMENT")

  ---
  Test 2: Camera Directions in Stage 5 (Phase C)

  Where: Stage 5 — World Building / Assets

  1. Navigate to Stage 5 for a project with location assets
  2. Click the three-dot menu (⋯) on a location asset card
  3. Verify: You see a "Camera Directions" menu item with a MapPin icon (this only  
  appears for location type assets, not characters or props)
  4. Click "Camera Directions" — a dialog should open

  Empty State:
  5. If no views exist yet, verify: You see an empty state with a compass icon and a   "Suggest Default Views" button
  6. Click "Suggest Default Views"
  7. Verify: 3 views are created:
  - Establishing (view_type: establishing) — overhead/wide for INT, eye_level/wide  
  for EXT
  - Direction 1 (view_type: direction, is_primary: true) — eye_level/wide
  - Direction 2 (view_type: direction) — eye_level/wide
  8. Verify: Direction 1 has a star icon indicating it's the primary/fallback       
  direction

  Editing Views:
  9. Click the edit (pencil) icon on a direction
  10. Type an alias (e.g., "stove wall") and description
  11. Click the check/save icon
  12. Verify: Alias and description persist after closing and reopening the dialog  

  Image Upload:
  13. Click the image area or upload button on a direction
  14. Select an image file
  15. Verify: Image uploads and appears as a thumbnail in the view card
  16. Verify: The dialog header updates the image count ("2/3 views have images")   

  Primary Toggle:
  17. Click the star icon on Direction 2
  18. Verify: Direction 2 becomes primary (filled star), Direction 1 loses primary  
  (outline star)
  19. Only one direction can be primary at a time

  Add Custom Direction:
  20. Click "Add Direction" button
  21. Fill in alias and description, click Add
  22. Verify: New "Direction 3" appears in the grid

  Delete:
  23. Delete a direction
  24. Verify: It disappears from the grid; if it had an image, the image is cleaned 
  up

  ---
  Test 3: Shot Extraction with Directions (Phase D)

  Where: Stage 7 — Shot List

  1. Navigate to Stage 7 for a scene that has a location asset
  2. Scenario A — Directions already exist (from Stage 5):
    - Extract shots for the scene
    - Verify (in the database or via network tab): Each shot has camera_distance,   
  camera_height, camera_movement fields populated
    - Verify: Each shot has a camera_direction_id pointing to an existing
  location_view
  3. Scenario B — No directions exist yet:
    - Use a scene whose location has no camera directions defined
    - Extract shots
    - Verify: New location_views records are created with source: 'stage7_inferred' 
    - Verify: These inferred directions have names like "direction_1", "direction_2"   with aliases and descriptions the LLM generated
    - Verify: Shots are assigned to these new directions
  4. After extraction, open the Camera Directions dialog in Stage 5 for that        
  location
  5. Verify: The inferred directions appear with an "Inferred" source badge and no  
  images

  ---
  Test 4: Coverage Panel (Phase E)

  Where: Stage 8 — Visual Definition

  1. Navigate to Stage 8 for a scene that has shots with direction assignments      
  2. Verify: Below the main visual editor panel, you see the Location Coverage Panel  3. Verify: Each location shows as a collapsible section with a coverage summary   
  ("X/Y shots covered")

  Direction Groups:
  4. Expand a location section
  5. Verify: You see direction groups, each showing:
  - Direction name and alias
  - Source badge (User / Established / Inferred)
  - Number of shots assigned
  - Thumbnail of the reference image (or placeholder if no image)
  - Coverage status icon (green check if has image, warning if no image)

  Unmatched Shots:
  6. If there are shots not assigned to any direction, verify: An "Unmatched"       
  section appears
  7. Verify: Each unmatched shot has a dropdown to assign it to a direction
  8. Select a direction from the dropdown
  9. Verify: The shot moves from "Unmatched" to the chosen direction group; coverage   count updates

  ---
  Test 5: View Image Generation (Phase H)

  Where: Stage 8 — LocationCoveragePanel

  Prerequisites: At least one location must have at least one reference image       
  (establishing or direction or master asset image)

  Per-direction generation:
  1. Find a direction that has no image but the location has at least one other     
  image
  2. Verify: A small Sparkles icon button appears next to the direction
  3. Click the Sparkles button
  4. Verify: A loading spinner appears on that direction row
  5. Verify: After generation completes, the image appears in the direction
  thumbnail
  6. Verify: A success toast notification appears

  Batch generation:
  7. Ensure a location has multiple directions without images
  8. Verify: At the bottom of that location's section, a "Generate N Missing Views" 
  button appears (where N is the count)
  9. Click it
  10. Verify: Directions generate sequentially (you see spinners appear one at a    
  time)
  11. Verify: After all complete, all previously-missing directions have images     

  No reference available:
  12. If a location has zero images anywhere (no establishing, no direction images, 
  no master asset image)
  13. Verify: The generate buttons do NOT appear (they require at least one
  reference to use as style input)

  ---
  Test 6: Prompt Generation with Location Views (Phase F)

  Where: Stage 9 — Prompt Generation (verify via network requests)

  1. Navigate to Stage 9 for a scene with location directions that have images      
  2. Generate prompts for the scene
  3. Open browser DevTools → Network tab, find the prompt generation API call       
  4. Verify in the response payload:
    - Location assets have matched_direction_view populated (the best-matching      
  direction for each shot)
    - Location assets have establishing_view populated (if an establishing view     
  exists)
    - reference_image_order entries for locations have role: "style" (not
  "identity")
    - If the shot's camera angle doesn't perfectly match the direction,
  location_delta_description contains a delta sentence
  5. Verify in the prompt text:
    - Location context includes the direction alias and description
    - If there's a delta, the prompt includes language like "The attached location  
  reference shows... Frame this shot from a [different angle]..."
    - The numbered image manifest shows 2 location entries: one labeled "MAIN       
  REFERENCE" and one labeled "SPATIAL CONTEXT"

  ---
  Test 7: Established Views (Phase G)

  Where: Stage 10 — Frame Generation

  Gap-fill scenario (direction has NO existing image):
  1. Navigate to Stage 10 for a scene with shots assigned to directions
  2. Ensure at least one direction has no reference image yet
  3. Generate a frame for a shot assigned to that imageless direction
  4. After the frame generates successfully, look below the frame panel
  5. Verify: A prominent emerald/green banner appears saying "This fills a coverage 
  gap!"
  6. Verify: The banner shows the location name and direction label
  7. Verify: A "Lock as Established View" button is visible
  8. Click "Lock as Established View"
  9. Verify: Success feedback; the frame's image is now the direction's reference   
  image
  10. Navigate back to Stage 5 → Camera Directions dialog
  11. Verify: The direction now shows the established image with an "Established"   
  source badge and provenance text ("Scene X, Shot Y")

  Replace scenario (direction already HAS an image):
  12. Go back to Stage 10, generate another frame for a shot assigned to a direction   that already has an image
  13. Verify: Instead of a prominent banner, you see a subtle text link: "Lock as   
  established view for [direction name]"
  14. Click the text link
  15. Verify: A confirmation dialog appears with side-by-side comparison (current   
  reference vs. new frame)
  16. Click "Replace"
  17. Verify: The direction's reference image is updated to the new frame

  No direction assigned scenario:
  18. If a shot has no camera_direction_id, verify: No EstablishViewPrompt appears  
  below the frame

  ---
  Test 8: End-to-End Flow

  Run through the full pipeline for a single scene:

  1. Stage 3–4: Generate script with compound headings → extract dependencies with  
  sub-locations
  2. Stage 5: Open Camera Directions on a location → Suggest defaults → Upload or   
  skip images
  3. Stage 7: Extract shots → Verify directions are created/assigned automatically  
  4. Stage 8: Check coverage panel → Assign any unmatched shots → Optionally        
  generate missing view images
  5. Stage 9: Generate prompts → Verify location refs appear as role: 'style' in    
  network
  6. Stage 10: Generate frames → Lock an approved frame as established view → Verify   it feeds back into the location's direction library

  Verify the consistency loop: After establishing a view in Step 6, generate another   frame for the same direction. The new frame should now use the established view  
  as its style reference, producing more visually consistent results.
