## Location Asset & Background Continuity — Feature Rethink

### Core Principle
- The multi-directional location shot feature should **not be the default** — it's opt-in for power users
- The default experience should be simpler, lower-friction, and require fewer generations

---

### Default Behavior (New)
- A single establishing/overview shot per location asset is sufficient for most users
- The image can be attached as a **low-weight style reference** rather than a precise background definition
- The LLM should be prompted to interpret the reference flexibly — e.g. if given a 3D overhead shot but the scene calls for eye-level, it should adapt intelligently without requiring the user to pre-define that
- Users can also skip uploading an image entirely and rely on a strong **text description** for the location asset, which gets appended to the frame prompt

---

### Power User / Opt-In Mode (Existing Feature, Preserved)
- Users who want maximum continuity and precision can **toggle on** multi-directional shot generation
- This produces directional/establishing shots for use as targeted background references
- Intended for highly detail-oriented users with higher generation budgets

---

### New Feature: Drag & Drop Frame Reuse
- Stage 10 should become the primary **creative control space** — the place where users make final decisions
- Users should be able to **drag frames from previous generations** into the current frame they're working on, as a background/composition reference
- This is the key mechanism for achieving **continuity without the overhead** of multi-directional asset generation

**Why this works:**
- Reusing a prior frame as a base preserves background, lighting, and environment consistency
- The user then **edits that frame** (via image editing / prompt) rather than generating from scratch
- Only the delta changes — new character poses, props, events — while the background stays stable
- Especially useful for: reverse shot/reverse shot sequences, long scenes in a fixed environment, recurring locations across scenes

**Drag & Drop UX rationale:**
- Visually intuitive — user sees exactly what they're pulling in
- Provides a "source of truth" starting point even when many details need to change (different characters, actions, props, etc.)
- Reduces the risk of environment drift that comes from repeatedly regenerating off a single vague establishing shot

---

### Summary of Changes
| | Before | After |
|---|---|---|
| Default location setup | Multi-directional shots | Single image or description |
| Background consistency method | Pre-defined directional assets | Drag & drop frame reuse + edit |
| Multi-directional shots | Always present | Opt-in toggle for power users |
| Stage 10 role | Generation stage | Primary creative / curation space |
