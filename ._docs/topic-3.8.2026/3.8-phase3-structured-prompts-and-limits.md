## Phase 3 — Structured Prompts Overhaul + Frame Prompt Limits (4C + Limits)

### Problem Statement
Two coupled issues: (1) Frame and video prompts are vague, unstructured paragraphs — not optimal for image/video generation. A 5-part structured formula was implemented but "poorly." (2) Frame prompts are getting cut off mid-generation by a hard character limit (1200 chars frame, 500 chars video), potentially losing critical visual details.

### Core Goal
Overhaul the prompt generation system to produce structured, deterministic prompts that leverage all prior stage data. Remove hard cutoffs and replace with warnings. Lay groundwork for future dynamic trimming.

**Backend (primary — this is mostly backend work):**
- `backend/src/services/promptGenerationService.ts` — PRIMARY FILE: `generatePromptSet()`, `generateBulkPromptSets()`, `buildAssetContext()`, `buildStyleContext()`, `buildNumberedImageManifest()`, `buildFrameReferenceManifests()`. System prompts for frame/video generation at ~lines 262-340. `cleanPromptOutput()` enforces character limits.
- `backend/src/services/contextManager.ts` — `formatPromptGenerationContext()`, asset truncation logic, token size monitoring (warns at 4000 tokens)
- `backend/src/services/prompt-template.ts` — template storage/interpolation (may be useful for structured templates)

**Frontend (secondary):**

### Current State

**Structured prompts (4C):** The 5-part frame prompt formula exists in the system prompt:
1. Camera Position & Framing
2. Subject Appearance
3. Spatial Placement & Pose
4. Environment & Props
5. Lighting, Color & Style

And the video prompt formula:
1. Camera Movement
2. Action/Performance
3. Dialogue
4. Sound Design

These are implemented but the spec says "poorly." Key issues:
- May not be pulling scene instance `effective_description` properly
- No provider-specific formatting (Veo3 vs future providers)
- Template isn't maintainable or testable
- Context manager may not feed rich enough data

**Prompt limits:** Backend enforces 1200 chars (frame), 500 chars (video) via `cleanPromptOutput()`. Frontend shows different thresholds. Prompts get truncated mid-sentence.

### Implementation Notes

#### Part A — Remove Hard Cutoffs, Add Warnings

**Step 1 — Backend: Remove truncation in `cleanPromptOutput()`:**
- Find `cleanPromptOutput()` in promptGenerationService.ts
- Remove the character-based truncation
- Add a `prompt_length_warning` field to the return type when prompts exceed threshold (e.g., 1200 chars frame, 500 chars video)
- Keep the thresholds as warning triggers, not cutoffs

**Step 2 — Frontend: Replace validation errors with warnings:**
- In `Stage9PromptSegmentation.tsx`: change the `FRAME_PROMPT_MAX` / `VIDEO_PROMPT_MAX` from blocking validation to amber warnings
- Display: "Prompt exceeds recommended length (X/1200 chars) — longer prompts may reduce generation quality"
- Allow user to proceed regardless

**Step 3 — Add length metadata to PromptSet:**
- Extend `PromptSet` type with optional `frameLengthWarning?: boolean`, `videoLengthWarning?: boolean`
- Return from generate-prompts endpoint so frontend can display inline

#### Part B — Structured Prompt Overhaul

**Step 4 — Audit current system prompt quality:**
- Read the exact system prompts in promptGenerationService.ts
- Compare against what the spec prescribes for each section
- Identify gaps: which sections are too vague? Which data sources are underutilized?

**Step 5 — Improve frame prompt system message:**
- Camera Position & Framing: Extract from shot `camera` field — shot type, angle, lens
- Subject Appearance: Pull from scene asset instances' `effective_description` (not just master description). Include status_tags for visual condition modifiers.
- Spatial Placement & Pose: Pull from enhanced shot `action` field (improved in Phase 2). Describe character positions, body language, spatial relationships.
- Environment & Props: Pull location asset description + prop descriptions from assigned assets
- Lighting, Color & Style: Pull from visual style capsule `design_pillars`, `descriptor_strings`, `negative_constraints`
- Enforce: NO action, NO dialogue, NO sound — frozen visual snapshot

**Step 6 — Improve video prompt system message:**
- Camera Movement: Extract movement verbs from shot `camera` field (pan, dolly, track, zoom, static)
- Action/Performance: Character actions, gestures from shot `action` field
- Dialogue: Exact words from shot `dialogue` field with delivery direction (tone, pace, accent)
- Sound Design: SFX and ambient audio inferred from scene context
- Enforce: NO character appearance, NO environment, NO lighting — action/audio focused

**Step 7 — Ensure all data sources are utilized:**
- Stage 4 master script excerpt (for narrative context)
- Stage 5 master asset descriptions + images
- Stage 7 shot list (enhanced from Phase 2)
- Stage 8 scene asset instances (effective_description, status_tags, scene-specific images)
- Style capsule directives
- Transformation events (for within-shot visual changes)

**Step 8 — Provider-specific formatting:**
- Add a provider parameter to prompt generation
- Veo3: optimize for its specific prompt format preferences
- Default/generic: current format
- Future extensibility for Sora, Runway, Kling

**Step 9 — Deterministic assembly:**
- Same inputs should produce same prompt structure (though LLM output varies)
- Consider: should we use template interpolation (prompt-template.ts) instead of LLM generation for the structural scaffold, with LLM only filling in creative gaps?

### Notables
- The frame/video prompt split is critical: frame = frozen visual snapshot, video = motion/audio direction. The boundary must be sharp.
- `cleanPromptOutput()` may do more than just truncation (stripping markdown, cleaning whitespace). Preserve those behaviors while removing the length cutoff.
- The `compatibleModels` field on PromptSet already filters providers by prompt length (e.g., Runway Gen-3 only if prompt <= 500). Removing cutoffs means updating this logic.
- Dynamic prompt trimming (detecting redundancy with attached reference images) is deferred to a follow-up spec. This phase just removes the hard cutoff.
