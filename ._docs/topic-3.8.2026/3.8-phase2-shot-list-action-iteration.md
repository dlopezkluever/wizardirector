## Phase 2 — Shot List Action Descriptions Iteration (4B.4)

### Problem Statement
Shot list entries extracted in Stage 7 lack the detail needed for quality frame/video prompts downstream. Actions are often just a line of dialogue with vague buzzwords. They need camera directions, character positioning, body language, environmental/lighting context, and crew-note style descriptions. This is the preamble to Stage 9 prompt generation — quality here directly impacts prompt quality.

### Core Goal
Iterate on the existing shot list extraction prompts to produce richer, more descriptive action fields that include camera direction, character choreography, body language, facial expression, and environmental context. Not a rewrite — improve what's there.

### Relevant Files

**Backend:**
- `backend/src/services/promptGenerationService.ts` — consumes shot data (action, camera, dialogue, setting fields) for prompt generation
- `backend/src/routes/projects.ts` — Stage 7 shot list extraction endpoint (search for "shot-list" or "extract-shots")
- Look for the LLM system prompt that instructs shot extraction — this is the primary target for iteration

**Frontend:**
- `src/components/pipeline/Stage7ShotList.tsx` (or similar) — shot list display UI
- `src/types/scene.ts` — Shot interface fields: `action`, `dialogue`, `camera`, `setting`, `characters_foreground`, `characters_background`, `continuity_flags`, `beat_reference`

### Current State
A previous implementation exists (marked "DONE KINDA") that enhanced extraction prompts. The current shot fields include `action`, `camera`, `dialogue`, `setting`, `characters_foreground/background`, `continuity_flags`, and `beat_reference`. The issue is that the extraction LLM prompt doesn't push hard enough for specificity in these fields.

### Implementation Notes

**Step 1 — Read current extraction prompt:**
- Find the LLM system prompt used for shot list extraction in Stage 7
- Assess: what instructions does it give for the `action` field? The `camera` field? The `setting` field?

**Step 2 — Enhance extraction instructions for each field:**
- `action`: Must describe physical choreography — character positions, body language, gestures, facial expressions, spatial relationships between characters. Not just "they talk" but "Character A leans forward across the table, pointing at Character B who recoils with arms crossed"
- `camera`: Must specify shot type (wide/medium/close-up/extreme close-up), angle (high/low/eye-level/dutch), lens feel (telephoto compression vs wide-angle distortion), AND any planned movement (dolly, pan, track, static)
- `setting`: Must describe the specific part of the location visible in this shot, lighting conditions, time of day cues, atmospheric elements
- `characters_foreground/background`: Must specify relative positions — left/center/right, distance from camera, facing direction

**Step 3 — Add crew-note style descriptors:**
- Instruct the LLM to think like a director giving notes to a cinematographer
- Example output style: "WIDE — Kitchen, morning light through window (camera-left). SPONGEBOB at stove (center-frame, back to camera), exaggerated chef posture, spatula raised theatrically. PATRICK enters from hallway (camera-right), sleepy slouch, dragging blanket."

**Step 4 — Body language & emotion specificity:**
- Instruct the LLM to describe HOW characters express emotion physically, not just name the emotion
- Bad: "angrily" — Good: "jaw clenched, shoulders raised, fists balled at sides, leaning forward into their space"
- Reference the spec example: "Spongebob has Chaplin-esque overly expressive, to a ridiculous degree, heavy emotional expressions in face"

**Step 5 — Validate with existing shots:**
- Re-extract shots for a test scene and compare old vs new output quality
- Check that the enhanced descriptions don't break any downstream consumers (Stage 9 prompt generation)

### Dependencies
- Phase 1 (4D.2) should land first — no point improving shot descriptions if reference images aren't reaching the API
- No schema changes required — this is purely LLM prompt engineering on extraction

### Notables
- The `camera` field serves double duty: Stage 9's frame prompt extracts static camera position from it, and video prompt extracts camera movement. Richer camera descriptions help both.
- Character angle matching (`mapCameraToAngleType()` in promptGenerationService) parses the `camera` field to select angle variants. More precise camera descriptions improve angle matching accuracy.
- This is prompt engineering work — results are probabilistic. Multiple iteration rounds may be needed.

### Verification
1. Pick a scene with varied shot types (dialogue, action, transitions)

3. Compare action/camera/setting fields: are they meaningfully more descriptive?
4. Generate Stage 9 prompts from the enhanced shots — do frame/video prompts improve?
