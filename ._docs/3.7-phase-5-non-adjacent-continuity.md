# Phase 5: Non-Adjacent Frame Continuity References (Task 5)

## Core Goal
Allow users to manually link non-adjacent frames as continuity references for each other, enabling proper shot-reverse-shot patterns and other non-linear continuity needs.

---

## Problem Statement
The current continuity system only considers adjacent shots. A shot-reverse-shot pattern alternates between two camera positions: shots 1, 3, 5 share one angle, and shots 2, 4, 6 share another. Adjacent frame references fail here — shot 3 needs shot 1's output as its reference, not shot 2's.

---

## Current State

### Existing Continuity System
- **`determineContinuityLink()`**: Compares adjacent shots' camera fields. Same camera = `match` (pixel copy), different camera same setting = `camera_change` (recomposition), otherwise `none`.
- **`frame_links` table**: Stores links between frames with `link_type: 'reference'`. Currently used for adjacent continuity links.
- **Camera change recomposition**: When `camera_change` is detected, the previous shot's end frame is vision-analyzed and a recomposition prompt is generated.
- **`start_continuity` field on shots**: User-selectable override (none/match/camera_change) with AI recommendation (`ai_start_continuity`).

### What's Missing
- No way to link shot 3 to shot 1 (skipping shot 2)
- No many-to-many linking model
- No UI for selecting non-adjacent references
- The continuity system is strictly sequential: "previous shot" means N-1

---

## Implementation Notes

### Data Model Extension

The existing `frame_links` table already supports arbitrary frame-to-frame links. The gap is in the UI and the frame generation logic that only checks the immediately previous shot.

**New field on shots table** (or use existing `frame_links`):
```typescript
// Option A: Explicit reference shot field
shot.continuity_reference_shot_id: string | null  // Links to a non-adjacent shot

// Option B: Use frame_links with a new link_type
frame_links.link_type: 'continuity_reference'  // Non-adjacent continuity link
```

Recommendation: **Option B** — use existing `frame_links` table with a `continuity_reference` link type. This is more flexible and doesn't require schema changes to the shots table.

### User Workflow

**Stage 10 (Frame Generation) UI**:
1. Each shot card has a "Continuity Reference" section
2. By default: shows the AI-recommended reference (adjacent shot) with the current mode (match/camera_change/none)
3. New: "Link to different shot" button opens a shot picker
4. Shot picker shows all shots in the scene with thumbnails of their start/end frames
5. User selects a non-adjacent shot as the reference
6. The linked shot's end frame becomes the continuity reference for this shot's start frame generation

**Visual indicators**:
- Shots with non-adjacent links show a colored connector line (not just sequential arrows)
- Shot-reverse-shot patterns could be auto-detected and suggested: "Shots 1, 3, 5 share camera setup A. Link them?"

### Frame Generation Logic Changes

**`frameGenerationService.ts`**:

Currently, for `camera_change` mode:
```typescript
const referenceFrame = previousShot.endFrame;  // Always N-1
```

Change to:
```typescript
// Check for explicit continuity reference link first
const continuityLink = await getContinuityReferenceLink(shot.id);
const referenceFrame = continuityLink
  ? await getFrameById(continuityLink.source_frame_id)  // Non-adjacent reference
  : previousShot?.endFrame;  // Fallback to adjacent
```

For `match` mode with non-adjacent reference:
- Instead of copying N-1's end frame, copy the linked shot's end frame
- This enables shot-reverse-shot: shot 3 copies shot 1's end frame exactly

### Auto-Detection of Shot-Reverse-Shot Patterns

Optional enhancement: after `determineContinuityLink()` runs for all shots, detect patterns:
1. Parse camera fields for all shots in the scene
2. Group shots by similar camera setup (same angle + shot type)
3. If alternating groups are detected (A-B-A-B), suggest linking:
   - "Shots 1, 3, 5 share camera setup. Link 3→1 and 5→3 for consistency?"
4. User confirms or dismisses the suggestion

[UNRESOLVED] Whether auto-detection should happen in Stage 9 (during prompt generation) or Stage 10 (during frame generation setup). Stage 9 is earlier and could inform prompt generation; Stage 10 is where the user actively manages frame references.

## Notables
- The many-to-many linking model is straightforward with `frame_links` — each link is a row, multiple links per frame are natural. No new table needed.
- Shot-reverse-shot auto-detection is a nice-to-have, not MVP. Manual linking alone solves the core problem.
- This feature has low blast radius — it extends existing infrastructure rather than replacing it. The fallback to adjacent references means existing behavior is preserved for shots without explicit links.
- Testing: create a scene with an A-B-A-B shot pattern, manually link A shots together, generate frames, verify visual consistency between linked shots.
