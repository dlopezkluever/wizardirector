     Analysis, Established Views (hero frames)
        - **`location_views` table**: FK to `project_assets`, supports        
     `establishing` + `direction` view types, `is_primary` fallback semantics 
     (eye-level Direction 1, NOT establishing), `source` tracking
     (user/established/stage7_inferred)
        - **Deterministic shot-to-direction matching**: Scoring algorithm     
     (height:+2, distance:+1, alias keyword:+3), fallback to `is_primary`, no 
     LLM
        - **2-ref location pattern**: Each location gets 2 reference images in      manifests — matched direction (MAIN REFERENCE) + establishing (SPATIAL  
     CONTEXT), both with `role: 'style'`
        - **Delta descriptions**: When reference image doesn't perfectly match      shot's camera angle, an explicit delta description is included in the   
     prompt
        - **REFERENCE_TYPE_STYLE**: Location refs use `role: 'style'` (not    
     'identity' like characters/props) — captures visual tone, color palette, 
     atmosphere
        - **Scene bible pattern**: Direction alias, description, and delta    
     injected into `buildAssetContext()` for repeatable location descriptions 
     across prompts
        - **Reference image flow**: Prompt generation (Stage 9) → stored on   
     `shots.reference_image_order` → used during frame generation (Stage 10)
